# Client 可安装插件实施计划

状态：实现计划；2026-10-10。桌面路线已确定为 React + TypeScript + Tauri 2 + Rust；本文所述插件包、SDK、隔离机制和装载流程尚未实现或验证。阶段安排见[桌面实施计划](../implementation.md)，能力语义见[音频与插件设计](../audio-processing.md)。

## 1. 交付范围与边界

Client 自行实现用户可安装的 MusicFS 插件体系，完整桌面首版覆盖 `theme`、`audio.demux`、`audio.decode`、`audio.dsp` 与 `control.api`；C3 先交付可安装音频插件及外部控制，C4 交付用户主题。安装兼容插件包后，宿主应从磁盘发现并装载，不要求重新编译客户端。内置注册表测试不能替代这一验收。

Tauri 框架插件用于窗口、快捷键及系统能力接入，按应用依赖管理；MusicFS 插件由 Client Plugin Host 管理安装、兼容性、权限和运行状态。两者使用独立的身份、版本及权限清单，不将第三方包直接注册成拥有应用权限的 Tauri 插件。[Tauri 插件开发说明](https://v2.tauri.app/develop/plugins/)

| 模块 | 拟承担的实现职责 |
| --- | --- |
| React 插件管理页 | 安装文件选择、包信息、权限展示、启停、配置、更新及回滚；仅消费宿主快照和提交命令 |
| Client Plugin Host（Rust） | 安装事务、兼容性与信任检查、注册表、运行实例、超时、取消、隔离策略和故障记录 |
| Native Audio Engine（Rust） | 持有音频图及插件实例租约，管理原生缓冲、背压、设备输出及图切换 |
| PluginWorker | 承载第三方原生库或独立插件程序，按宿主授权提供受限的控制与数据通道 |
| PlayerCore（Rust） | 唯一播放状态所有者；决定播放代次、命令顺序、图更换、失败恢复及对外快照 |

插件不能持有可写的 PlayerCore 状态，也不能从 React 直接调用解码或 DSP。FFmpeg 为跨平台解码候选，设备输出库与 WMF 可选适配仍需 C0 验证；C/C++ 实现通过版本化 C ABI 适配接入，不与 Rust/React 直接交换语言对象。

## 2. 包格式与安装目录

拟定义 `.mfplugin` 归档包，格式和 Schema 在 C0 冻结前均为建议。包包含 `manifest.json`、声明式主题资源，或按 target 分组的动态库、worker 与必要依赖。首版不支持安装脚本、在线执行脚本或从包内自动运行任意构建命令。

安装根位于应用用户数据目录。按 `pluginId/version/packageDigest` 保存不可变包内容；活动版本、启用偏好和配置由宿主单独维护。程序安装目录中的内置包只读，用户包不能凭相同 ID 替换内置包。完整性摘要不能证明发布者可信，信任来源须单独记录。

| manifest 建议字段 | 含义与校验 |
| --- | --- |
| `schemaVersion` | 包清单格式版本；未知主版本拒绝安装 |
| `id`、`version`、`name`、`description` | 稳定插件 ID、语义版本及展示信息；同 ID/版本不同摘要视为冲突 |
| `publisher`、`license` | 发布者与许可信息；文本声明不能授予内置信任 |
| `clientVersionRange`、`hostSdkVersionRange` | 客户端及 MusicFS 插件 SDK 的兼容范围 |
| `capabilities` | 声明能力及各自接口版本；仅允许宿主已知能力 |
| `entrypoints` | 每个 target 的入口类型、相对路径、ABI/worker 协议版本及依赖；主题使用资源入口 |
| `targets` | OS、CPU 架构、ABI、最低系统或运行时要求；不能只写操作系统名称 |
| `files` | 包内文件路径、大小与摘要，覆盖入口及其依赖；摘要算法固定在包 Schema 中 |
| `permissions` | 所需宿主服务与具体作用范围；缺失权限默认拒绝 |
| `configuration` | 配置 Schema 路径、版本及兼容范围；敏感值不放入普通配置 |
| `audio` | 支持的输入/输出格式、块尺寸边界、seek/reset、drain、延迟与尾音能力 |
| `themeApiVersion` | 主题 token 与资源接口版本，仅主题能力需要 |

同一包可包含多个 target，也允许每个平台单独分发；签名、来源记录与完整性校验须覆盖实际安装内容。签名封装和发布者信任根是 C0 待定项，确定前不宣称具备可验证发布者体系。

安装按以下事务执行：

1. 将包复制到宿主管理的临时目录，限制压缩前后大小、文件数量与路径长度。
2. 验证归档结构，拒绝绝对路径、路径穿越、重复/大小写冲突路径及可逃逸的链接；所有输出仍须落在临时根内。
3. 校验清单、目标平台、接口版本、文件摘要和发布来源，再呈现权限；安装阶段不执行原生入口。
4. 原子发布到不可变版本目录，记录 `installed_disabled`。中断或校验失败不改动旧活动版本。
5. 用户启用后进入装载流程。权限增加、来源变化或兼容性变化须重新评估，不能继承旧授权自动启用。

注册表记录安装事务与活动版本切换的持久状态；启动时清理未完成暂存并恢复已提交记录。安装完成只表示包已保存，启用成功才表示运行实例就绪。

## 3. 装载策略与兼容性

| 插件类型 | 首版装载策略 | 开放条件 |
| --- | --- | --- |
| 内置主题 | 声明式 token 与允许的资源 | 资源校验通过，默认主题始终可回退 |
| 用户主题 | 与内置主题相同的资源接口 | 不执行 JavaScript，不注入任意 HTML/CSS，不加载远程资源 |
| 受信任内置音频适配器 | 可进程内装载或编译内置，共用能力注册和生命周期接口 | 明确随客户端审核/发布；性能与内存测试通过 |
| 用户第三方原生音频插件 | 优先放入独立 PluginWorker，worker 再加载目标动态库；也可使用协议兼容的独立程序 | 对应平台的隔离、崩溃处理及音频数据面验证通过后才开放 |
| `control.api` | 独立受控实例，将请求转为 PlayerCore 命令 | 鉴权、作用范围、订阅回收与停用验证通过 |

`entrypoints` 只能声明包支持的执行方式，最终执行策略由宿主决定，包不能把自己标记成可信进程内插件。C0 可使用受控测试包验证进程内动态库，但不能据此默认开放任意第三方库加载到主进程。

装载前依次检查包摘要、平台 target、客户端/SDK 范围、能力接口及配置版本。动态库再检查导出入口和返回的 ABI 描述；worker 完成带随机会话标识、包摘要、实例 ID 与协议版本的握手。握手和能力探测具有有界超时，失败不发布为可用能力。

拟由 Rust 封装动态库装载，`libloading` 是候选实现。其库与符号生命周期约束并不代替 MusicFS 的 ABI 验证、信任判断及音频图引用管理。[libloading 文档](https://docs.rs/libloading/latest/libloading/)

兼容规则如下：

- C ABI 主版本不兼容即拒绝；次版本扩展使用结构体长度、能力位与可选函数协商，必需能力缺失即拒绝。
- 不承诺跨 OS、CPU、工具链 ABI 或 Client/Server 宿主的二进制通用；Linux 运行时、macOS 装载/签名策略等由实际发行矩阵验证。
- 入口与依赖只从经过校验的包目录和明确允许的系统库解析，不能依赖当前工作目录或可写目录中的同名库。
- 配置兼容、主题接口兼容、worker 协议兼容分别检查；包的语义版本号不能替代这些检查。
- 同插件不同版本允许并存，只有宿主选择的版本可接受新实例；旧版本仅为活动图收尾或回滚保留。

## 4. 原生 SDK 与数据通道

首版 SDK 先定义契约和最小样例，再冻结头文件/Schema。拟提供能力查询、实例创建、配置、start、cancel、seek/reset、flush、drain、错误读取与销毁；数据处理入口与控制入口分离。

进程内 C ABI 必须明确以下规则：

1. 仅使用固定宽度数值、带长度的字节区间、版本化结构和不透明句柄；字符串指定 UTF-8。Rust `Vec/String`、C++ STL 对象、虚表和引用计数实现不得跨界。
2. 分配方负责释放，使用配对释放函数或宿主提供的分配接口；禁止跨分配器释放。借用缓冲写明可变性、容量和有效期，异步保留须取得显式租约。
3. 每个入口声明可调用线程、串行/并发约束和重入规则。控制调用不得重入 PlayerCore；宿主回调先入队，再由状态所有者处理。
4. Rust panic 和 C++ 异常不得跨 ABI unwind；适配器在边界转换为错误码，明确不可恢复崩溃仍可能终止所在进程。
5. `cancel` 幂等且可使阻塞工作退出；销毁前须停止线程和所有回调。无法证明安全释放的进程内实例保留到应用退出，并标记需重启。

跨进程协议不传指针或 C ABI 结构体的原始内存布局。控制消息采用带长度、版本、请求 ID 和错误码的协议；具体编码在 C0 比较后确定。worker 的每次重启生成新装载代次，旧代次的结果、共享缓冲引用及回调全部失效。

PCM 只经过原生有界队列或受控共享缓冲，不经过 WebView、React 状态或连续 JSON/Base64 消息。缓冲描述包含实例/播放代次、序号、采样格式、采样率、声道布局、帧数、时间戳和时间基准；格式、尺寸及偏移由宿主验证，不能信任 worker 提交的长度。

共享缓冲须约定槽位所有权、读写次序、容量、回收与取消协议。数据区不能承载可执行地址或宿主指针；单独限制每实例内存、排队帧数和处理时间。worker 退出后，确认进程及映射生命周期结束再复用对应槽位。

设备回调只消费预先准备的音频块，不等待 worker、读盘、网络或插件控制响应。插件停顿/崩溃时按 PlayerCore 选择的策略停止或重建图；DSP 仅在明确允许并能保持格式/时间语义时旁路，解码失败不得按静音无限继续。队列水位、欠载和处理耗时用于 C0 记录数据面预算。

## 5. 启停、卸载与更新状态机

包安装状态与运行实例状态分开记录，UI 同时显示活动版本、待启用版本和失败原因，避免“安装成功”掩盖运行失败。以下状态名称为内部建议值，最终界面使用中文。

| 包状态 | 允许的下一步 |
| --- | --- |
| `staging` | 校验成功提交为 `installed_disabled`；失败清理暂存 |
| `installed_disabled` | 启用、删除或选择为回滚候选 |
| `enabled` | 创建新实例、请求停用或暂存新版本 |
| `pending_removal` | 禁止新实例，等待全部实例安全结束后删除 |
| `quarantined` | 展示失败原因，禁止自动启用；显式重试前重新验证 |

| 实例状态 | 进入条件与退出行为 |
| --- | --- |
| `loading` | 校验入口并加载/启动 worker；失败进入 `faulted` |
| `ready` | 握手、能力与配置完成；可申请加入音频图或接受受控请求 |
| `active` | 持有音频图租约或控制订阅；必须绑定装载代次 |
| `retiring` | 禁止新任务，取消在途操作，等待音频图、回调及订阅释放 |
| `stopped` | 实例资源已释放，可卸载库或清理进程 |
| `faulted` | 超时、崩溃或协议错误；失效结果并由 PlayerCore 执行恢复策略 |
| `restart_required` | 进程内实例无法安全退出；保持库及所需内存，禁止强制卸载 |

停用与卸载按“禁止新实例 → PlayerCore 取消旧任务并替换/停止图 → 释放图租约 → join 线程/结束 worker → 释放缓冲和符号 → 卸载库”执行。图租约覆盖实例、库句柄和回调数据，只有全部使用者退出后才能释放最后引用。

正常曲目结束可执行有界 drain，主动停止、取消或换图不等待无限尾音。连续切歌只接受最新播放代次；插件装载代次独立于播放代次，两者都匹配才能采用结果。不能以“已发出 cancel”推断数据面不再访问内存。

worker 超时可在撤销请求和隔离旧缓冲后终止；进程内超时不能强行卸载仍可能执行代码的库。删除被占用包时保留 `pending_removal` 并在安全退出后清理，不能删除后原地重写。

更新与回滚使用并存版本和提交点：

1. 完整安装新版本，保留旧版本及其配置快照；配置迁移只写新副本，不允许执行包内迁移脚本。
2. 对新版本重新进行兼容性、权限、信任和启动探测；未通过时旧版本继续工作。
3. PlayerCore 在安全图边界重建或切换；主题则在完整资源校验后整体替换。首版不承诺有声播放中的无缝原生热更新，必要时明确等待停止或重启。
4. 新实例就绪且切换成功后，原子提交活动版本及新配置；旧实例进入 `retiring`，不提前卸载。
5. 切换失败时恢复旧版本与配置快照，由 PlayerCore 重建可用图；不能保证续播时提示重新播放，不拼接旧解码状态。
6. 启动期间连续崩溃达到有限重试阈值后隔离问题版本，使用最近可用版本或禁用该插件；不无限重启 worker。阈值与日志保留量在 C0 测试后固定。

## 6. 权限、主题与外部控制

Tauri capabilities 管理 WebView 到原生命令的访问边界；它不是第三方原生代码的沙箱。独立 worker 能提供进程故障边界，但没有额外 OS 限制时仍可能拥有当前用户的文件与网络权限。[Tauri 权限边界](https://v2.tauri.app/security/capabilities/)

MusicFS 清单权限由宿主执行，建议最小集合如下：

| 权限 | 作用范围与实现要求 |
| --- | --- |
| `theme.resources` | 仅所安装主题的校验资源及允许 token；禁止远程 URL、脚本和任意路径 |
| `audio.input` | 本次授权输入的受控读取/定位能力；优先传数据句柄，不传 Server/Provider 凭据 |
| `audio.process` | 本实例的音频块、配置和格式协商，不开放设备及全局播放状态写权限 |
| `plugin.storage` | 该插件专属且有配额的目录；路径检查与 OS 隔离同时验证 |
| `player.read`、`player.control` | 允许的状态字段、操作集合及订阅；全部经过 PlayerCore |
| `control.listen` | 显式启用的本机监听或本地 IPC；远程监听单独授权 |

外部网络、设备、进程派生和任意文件访问默认不授予。第三方开放前须针对每个 target 验证 OS 隔离能否实际约束直接系统调用、子进程、句柄继承和网络；限制无法实现的能力应拒绝启用或保持未支持，不能只显示权限提示后宣称沙箱成立。

主题只提供声明式颜色、字体、尺寸与受限布局 token；React 负责将 token 映射为既定组件样式。资源损坏或接口不兼容时回到默认主题，更换主题不重启音频引擎。

`control.api` 默认关闭。启用后默认仅本机访问，使用独立可撤销 token；浏览器调用还验证来源。网络协议和本地 IPC 的具体选择留待原型验证。请求携带 `commandId` 和必要的播放代次/修订，经 PlayerCore 做鉴权、参数校验与去重；订阅带序号，缺失后重新获取快照。

远程监听须显式配置监听范围、鉴权和安全传输。停用时先停止接收请求，再撤销 token/订阅，不停止本机播放。播放控制权限不包含插件安装、权限变更、任意命令执行或凭据读取；调试日志使用英文且隐藏 token、私有地址和敏感头。

## 7. 实施顺序与验收

C0 先冻结最小包清单、C ABI 与 worker 协议草案，用一个主题包、一个增益 DSP 动态库和一个可注入故障的 worker 验证方案。记录各 target、系统、构建工具链、设备、块尺寸、欠载、CPU/内存及取消耗时；数值预算通过实测写入验证记录后才作为发布门槛。

后续按主计划交付安装事务、宿主 SDK、真实加载、管理页、更新回滚，再开放已通过隔离验证的第三方能力。每项验收使用打包后的应用及从磁盘安装的包；开发服务器和静态内置样例仅作辅助。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 应用发布后安装新的 DSP 包 | 不重新编译客户端，发现能力并实际改变测试音频；重启后仍能正确装载 |
| 三大平台及声明 CPU target | 主题可用，原生包只选择匹配入口；不匹配/缺依赖明确拒绝，不静默使用其他 ABI |
| 旧 ABI、未知必需能力、配置不兼容 | 执行原生入口前尽可能拒绝，握手不兼容时结束实例，旧活动版本保留 |
| 坏摘要、越界路径、链接逃逸、超大包 | 安装失败，未写出安装根，活动版本和配置不变 |
| 连续切歌、seek、取消后延迟返回 | 旧播放/装载代次输出被丢弃，状态、歌词和设备输出一致 |
| 活动图中停用或卸载 DSP | 安全替换或停止图后再卸载；无释放后使用、失效符号调用与残留线程 |
| worker 阻塞、崩溃或畸形 PCM 描述 | UI 保持可操作，回调不等待，错误可见且有界恢复；不越界读写或无限重启 |
| 进程内插件拒绝退出 | 标记需重启并保留必需引用，不强行卸载；后续安全退出可完成 |
| 更新中断、迁移失败、切换失败 | 旧版本及原配置可用；重启能从安装日志恢复明确状态 |
