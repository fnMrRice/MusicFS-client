# Client 可安装插件实施计划

状态：实现计划；2026-10-11。桌面路线已确定为 React + TypeScript + Tauri 2 + Rust；本文所述插件包、SDK 和装载流程尚未实现或验证。原生插件按用户选择统一在同一原生宿主进程内运行，不提供插件子进程模式。阶段安排见[桌面实施计划](../implementation.md)，能力语义见[音频与插件设计](../audio-processing.md)及[能力与宿主边界](../plugin-capabilities.md)。

## 1. 交付范围与边界

Client 自行实现用户可安装的 MusicFS 插件体系，完整桌面首版覆盖 `theme`、`audio.demux`、`audio.decode`、`audio.dsp`、`audio.output` 与 `control.api`；C3 交付可安装音频插件及外部控制，C4 交付用户主题，并细化 `audio.visualizer` 与 `control.integration` 扩展。安装兼容插件包后，宿主应在下次启动从磁盘发现并装载，不要求重新编译客户端。内置注册表测试不能替代这一验收。本期不提供插件卸载/删除功能；已加载动态库保留至原生宿主进程退出，不主动调用 `FreeLibrary` / `dlclose`。

Tauri 框架插件用于窗口、快捷键及系统能力接入，按应用依赖管理；MusicFS 插件由 Client Plugin Host 管理安装、兼容性、权限和运行状态。两者使用独立的身份、版本及权限清单，不将第三方包直接注册成拥有应用权限的 Tauri 插件。[Tauri 插件开发说明](https://v2.tauri.app/develop/plugins/)

| 模块 | 拟承担的实现职责 |
| --- | --- |
| React 插件管理页 | 安装、包信息、权限、配置；保存重启后启停/版本选择，同时展示当前状态与待生效状态 |
| Client Plugin Host（Rust） | 安装事务、兼容性与信任检查、注册表、运行实例、协作取消、动态库引用与故障记录 |
| Native Audio Engine（Rust） | 持有音频图及插件实例租约，管理原生缓冲、背压、设备输出及图切换 |
| 原生插件动态库 | 在宿主同一进程内提供版本化 C ABI；Windows DLL、macOS dylib、Linux so，各 target 独立验证 |
| PlayerCore（Rust） | 唯一播放状态所有者；决定播放代次、命令顺序、图更换、失败恢复及对外快照 |

契约不向插件提供可写的 PlayerCore 状态，也不能从 React 直接调用解码或 DSP。FFmpeg 为跨平台解码候选，设备输出库与 WMF 可选适配仍需 C0 验证；需要 C++ 的插件统一采用 CMake/C++23，通过版本化 C ABI 接入，不与 Rust/React 直接交换语言对象。共享构建与 ABI 规则见[原生插件规范](../../../docs/native-plugins.md)。Rust 核心保留，既有 C 库通过 C++23 适配层使用时不要求改写其实现语言。

同进程原生代码拥有宿主权限并能访问进程内存，清单权限与宿主 API 不是沙箱。启用前显示发布来源、实际 target 与这一信任边界；原生崩溃可能终止整个 Client。Tauri/WebView 可能使用系统辅助进程，但 MusicFS 插件不在其中运行。

## 2. 包格式与安装目录

拟定义 `.mfplugin` 归档包，格式和 Schema 在 C0 冻结前均为建议。包包含 `manifest.json`、声明式主题资源，或按 target 分组的动态库与必要依赖。原生入口只接受动态库，不接受插件可执行程序。首版不支持安装脚本、在线执行脚本或从包内自动运行任意构建命令。

安装根位于应用用户数据目录。按 `pluginId/version/packageDigest` 保存不可变包内容；活动版本、启用偏好和配置由宿主单独维护。程序安装目录中的内置包只读，用户包不能凭相同 ID 替换内置包。完整性摘要不能证明发布者可信，信任来源须单独记录。

| manifest 建议字段 | 含义与校验 |
| --- | --- |
| `schemaVersion` | 包清单格式版本；未知主版本拒绝安装 |
| `id`、`version`、`name`、`description` | 稳定插件 ID、语义版本及展示信息；同 ID/版本不同摘要视为冲突 |
| `publisher`、`license` | 发布者与许可信息；文本声明不能授予内置信任 |
| `clientVersionRange`、`hostSdkVersionRange` | 客户端及 MusicFS 插件 SDK 的兼容范围 |
| `capabilities` | 声明能力及各自接口版本；仅允许宿主已知能力 |
| `entrypoints` | 每个 target 的动态库相对路径、C ABI 版本、唯一查询符号及依赖；主题使用资源入口 |
| `targets` | OS、CPU 架构、ABI、最低系统或运行时要求；不能只写操作系统名称 |
| `files` | 包内文件路径、大小与摘要，覆盖入口及其依赖；摘要算法固定在包 Schema 中 |
| `permissions` | 所需宿主服务与具体作用范围；缺失权限默认拒绝 |
| `configuration` | 配置 Schema 路径、版本及兼容范围；敏感值不放入普通配置 |
| `audio` | 支持的输入/输出格式、块尺寸边界、seek/reset、drain、延迟与尾音能力 |
| `themeApiVersion` | 主题 token 与资源接口版本，仅主题能力需要 |
| `build` | CMake/编译器/标准库版本、C++23 配置、依赖锁摘要与构建标识；不能替代装载验证 |

同一包可包含多个 target，也允许每个平台单独分发；签名、来源记录与完整性校验须覆盖实际安装内容。签名封装和发布者信任根是 C0 待定项，确定前不宣称具备可验证发布者体系。

安装按以下事务执行：

1. 将包复制到宿主管理的临时目录，限制压缩前后大小、文件数量与路径长度。
2. 验证归档结构，拒绝绝对路径、路径穿越、重复/大小写冲突路径及可逃逸的链接；所有输出仍须落在临时根内。
3. 校验清单、目标平台、接口版本、文件摘要和发布来源，再呈现权限；安装阶段不执行原生入口。
4. 原子发布到不可变版本目录，记录 `installed_disabled`。中断或校验失败不改动旧活动版本。
5. 用户请求启用只保存 `desiredEnabled=true` 并显示“重启后生效”，初次安装也遵循此规则；下次启动才进入装载流程。权限增加、来源变化或兼容性变化须重新评估，不能继承旧授权自动启用。

注册表记录安装事务与待启动版本的持久状态；启动时清理未完成暂存并恢复已提交记录。安装完成只表示包已保存，启用请求已保存不等于本次进程已加载。失败安装的临时目录清理不等于提供已安装插件的卸载功能。

## 3. 装载策略与兼容性

| 插件类型 | 首版装载策略 | 开放条件 |
| --- | --- | --- |
| 内置主题 | 声明式 token 与允许的资源 | 资源校验通过，默认主题始终可回退 |
| 用户主题 | 与内置主题相同的资源接口 | 不执行 JavaScript，不注入任意 HTML/CSS，不加载远程资源 |
| 受信任内置音频适配器 | 在原生宿主进程内装载动态库或编译内置，共用能力注册和生命周期接口 | 明确随客户端审核/发布；性能与内存测试通过 |
| 用户原生音频/输出/分析插件 | 启动时在同一原生宿主进程内装载对应 target 的动态库，句柄保留到退出 | ABI、依赖、实例回收、重启启停/恢复及数据面通过；启用者理解同进程信任边界 |
| `control.api` / `control.integration` | 同进程动态库实例，将外部请求转为 PlayerCore 命令 | 鉴权、作用范围、订阅与系统回调回收验证通过 |

`entrypoints` 只能声明动态库或主题资源入口；清单不能自授内置信任，未知类型直接拒绝。外部包只有在用户明确启用、目标兼容及验证通过后才装载，但来源/签名验证本身不能证明原生代码安全。

装载前依次检查包摘要、平台 target、客户端/SDK 范围、能力接口及配置版本。加载动态库后检查唯一查询入口及其返回的 ABI 描述，协商角色接口，再分配实例与装载代次。动态库加载可执行静态初始化，因此来源/用户启用和可静态检查的兼容性必须在加载前完成。查询与能力探测由非 UI 线程计时；超时不发布能力，但无法强制终止同进程代码，必须进入需重启处理。

拟由 Rust 封装动态库装载，`libloading` 是候选实现。其库与符号生命周期约束并不代替 MusicFS 的 ABI 验证、信任判断及音频图引用管理。[libloading 文档](https://docs.rs/libloading/latest/libloading/)

兼容规则如下：

- C ABI 主版本不兼容即拒绝；次版本扩展使用结构体长度、能力位与可选函数协商，必需能力缺失即拒绝。
- 不承诺跨 OS、CPU、工具链 ABI 或 Client/Server 宿主的二进制通用；Linux 运行时、macOS 装载/签名策略等由实际发行矩阵验证。
- 入口与依赖只从经过校验的包目录和明确允许的系统库解析，不能依赖当前工作目录或可写目录中的同名库。
- 配置兼容、主题接口兼容、C ABI 和各角色接口兼容分别检查；包的语义版本号不能替代这些检查。
- 同插件不同版本的包目录允许并存，每次进程启动只选择一个版本；新旧库不为更新或回滚在同一进程中交替加载。旧包保留供后续重启回滚。

## 4. 原生 SDK 与数据通道

首版 SDK 先定义契约和最小样例，再冻结头文件/Schema。拟提供能力查询、实例创建、配置、start、cancel、seek/reset、flush、drain、错误读取与销毁；数据处理入口与控制入口分离。CMake 构建样例至少有增益 DSP 和输出适配样例；C++23 只用于库内部，公开头文件保持可从 C/Rust FFI 使用，不导出 C++ 模板或类。

进程内 C ABI 必须明确以下规则：

1. 仅使用固定宽度数值、带长度的字节区间、版本化结构和不透明句柄；字符串指定 UTF-8。Rust `Vec/String`、C++ STL 对象、虚表和引用计数实现不得跨界。
2. 分配方负责释放，使用配对释放函数或宿主提供的分配接口；禁止跨分配器释放。借用缓冲写明可变性、容量和有效期，异步保留须取得显式租约。
3. 每个入口声明可调用线程、串行/并发约束和重入规则；默认实例调用串行。取消由 Host 原子令牌或声明可并发且非阻塞的专用入口提供，不能排在正在阻塞的 `process` 后面。控制调用不得重入 PlayerCore；宿主回调先入队，再由状态所有者处理。
4. Rust panic 和 C++ 异常不得跨 ABI unwind；适配器将可捕获且能安全返回的错误转换为错误码。访问违例、堆破坏、栈损坏及未定义行为不保证可捕获或恢复，可能终止整个 Client。
5. `cancel` 幂等，插件必须定期检查取消并提供合作式退出；此为契约义务，不保证任意原生代码都能退出。销毁前须停止线程和所有回调。无法证明安全释放的实例保留库及相关资源到应用退出，并标记需重启。

Client 插件不定义跨进程数据通道。启动装载生成装载代次，每次实例重建另生成实例代次；旧实例结果、缓冲和回调不能用于新实例，实例销毁不改变库引用。C ABI 调用可以使用限定生存期的本机指针，但指针不可序列化、写入持久配置或传至 React；释放前须核实对应借用或租约已结束。

PCM 只经过进程内原生有界队列或带租约的缓冲，不经过 WebView、React 状态或连续 JSON/Base64 消息。缓冲描述包含实例/播放代次、本机 `graphGeneration`、序号、采样格式、采样率、声道布局、帧数、时间戳和时间基准；格式、尺寸及偏移由宿主验证，不能无条件采用插件提交的长度。边界校验减少合作代码的错误，不构成针对恶意内存写入的保护。

缓冲须约定槽位所有权、读写次序、容量、回收与取消协议，音频样本区不承载可执行地址。通过宿主分配器限制申请量、排队帧数并计量处理时间；插件直接分配或消耗 CPU 无法在此模式下硬性隔离。确认所有调用、回调和线程不再访问后才能复用对应槽位，取消请求已发出不代表这一条件已满足。

设备回调只消费预先准备的音频块，不等待读盘、网络或插件控制响应。宿主仍可运行且插件正常返回错误时，由 PlayerCore 选择停止或重建图；DSP 仅在明确允许并能保持格式/时间语义时旁路，解码失败不得按静音无限继续。插件卡死时停止向其提交工作并保留引用，不能以图重建为由复用仍被访问的内存；崩溃则可能直接结束 Client。队列水位、欠载和处理耗时用于 C0 记录数据面预算。

## 5. 重启启停与版本状态

包安装状态、用户期望状态、本次进程状态和播放实例状态分开记录。以下字段和状态名为内部建议值，界面使用中文，并明确展示“当前已启用 / 下次启动禁用”“当前版本 / 待生效版本”；没有插件删除入口。

| 注册表字段 | 语义 |
| --- | --- |
| `installedVersions` | 已校验的不可变包目录与摘要；本期保留已安装版本 |
| `desiredEnabled` | 用户期望下次启动的启用值；修改立即持久化，不改变本次进程能力 |
| `desiredVersion` | 下次启动选择的已校验版本；更新与回滚均只修改此值 |
| `effectiveEnabled` / `effectiveVersion` | 本次启动完成校验后实际装载的状态；不能因用户改期望值而冒报改变 |
| `restartPending` | 期望值与当前值不一致；界面提示重启，允许撤销待生效选择 |
| `blockedReason` | 兼容失败、启动失败或疑似崩溃等禁止自动装载原因；与用户偏好分开 |

用户停用只写 `desiredEnabled=false`。当前活动版本及能力保持到退出，仍可为正常播放创建实例；不撤销图、停止监听或注销系统回调。功能本身故障导致实例不可用另行报告，不能伪装成停用已生效。启用、初次安装后启用、更新与回滚同样仅在重启后生效。重启必须结束原生宿主进程，刷新或关闭 WebView 不算重启。

| 播放/能力实例状态 | 进入条件与退出行为 |
| --- | --- |
| `ready` | 启动完成 ABI/角色协商与配置，可创建任务实例 |
| `active` | 持有音频图租约或控制订阅，绑定实例及播放/图代次 |
| `retiring` | 曲目结束、换图、设备关闭或应用退出，取消该实例任务并排空 |
| `stopped` | 该实例资源、线程和回调已释放；所属动态库继续保留 |
| `faulted` | 可返回的处理/配置错误，由 PlayerCore 处理；进程崩溃不保证能记录此状态 |
| `restart_required` | 在途调用或线程无法协作退出，保留实例及相关内存并提示重启 |

正常播放仍允许创建/销毁实例、seek/reset、取消和换图；这些操作不改变插件启用状态、不卸载库。实例销毁按“停止该实例新业务 → 取消任务 → 停止相应输出/系统回调 → 等待在途调用和线程 → 归还图/缓冲租约 → 销毁实例”执行。保留排空所需的生命周期入口与完成回调，等待不在 UI 或音频回调中阻塞。宿主注册表强持有所有已加载库和函数表，避免语言对象析构意外卸载库，包括加载后发现 ABI 不兼容的库。

正常曲目结束可执行有界 drain，主动停止、取消或换图不等待无限尾音。连续切歌只接受最新播放代次；实例代次、本机图代次独立于播放代次，全部匹配才能采用结果。纯本机换图不要求 Server 产生新 attempt，服务端资源/处理输出变化才重新协商。不能以“已发出 cancel”推断数据面不再访问内存。

应用退出时停止所有新业务、取消任务、停止回调并尽力完成有界排空，再结束原生进程，由操作系统回收库。超时不能强杀插件线程后继续使用进程内存；保留仍可能被访问的实例/缓冲，不主动卸载库。若插件使进程卡死，不能保证正常退出或界面仍响应，可能需要用户结束整个应用。

更新与回滚统一在重启后激活，不提供运行中版本切换：

1. 安装并静态校验候选版本，保留旧包和旧配置快照；配置迁移只写新副本，不执行包内迁移脚本。
2. 保存 `desiredVersion` 和必要授权，显示“重启后生效”；不为探测而在本次进程提前加载候选库。
3. 下次启动只装载本次选定版本。探测及配置成功后提交 `effectiveVersion`；失败时保留原包、配置和恢复入口，不在同一进程内改加载旧版本。
4. 回滚只把期望版本指向旧包及对应配置，下一次重启后再应用；恢复播放重新读取 Server 状态，不拼接旧解码状态。
5. 加载前记录运行标记，正常退出清除；未完成记录提供“禁用用户插件启动”入口，连续失败达到有限阈值后阻止疑似版本自动加载，不无限自动重启。可疑记录不能替代根因诊断，阈值和日志量在 C0 固定。

## 6. 权限、主题与外部控制

Tauri capabilities 管理 WebView 到原生命令的访问边界；它不是第三方原生代码的沙箱。本设计将所有原生插件加载到 Rust 宿主同一进程，插件拥有与宿主相同的系统权限；清单只限制经宿主服务发起的操作。[Tauri 权限边界](https://v2.tauri.app/security/capabilities/)

MusicFS 清单权限由宿主执行，建议最小集合如下：

| 权限 | 作用范围与实现要求 |
| --- | --- |
| `theme.resources` | 仅所安装主题的校验资源及允许 token；禁止远程 URL、脚本和任意路径 |
| `audio.input` | 本次授权输入的受控读取/定位能力；优先传数据句柄，不传 Server/Provider 凭据 |
| `audio.process` | 本实例的音频块、配置和格式协商，不开放设备及全局播放状态写权限 |
| `plugin.storage` | 经宿主服务访问该插件专属且有配额的目录；路径校验不阻止原生代码直接读其他路径 |
| `player.read`、`player.control` | 允许的状态字段、操作集合及订阅；全部经过 PlayerCore |
| `control.listen` | 显式启用的本机监听或本地 IPC；远程监听单独授权 |
| `audio.output` | 经宿主选择的设备及其回调租约；插件不通过服务改写全局时钟 |
| `audio.observe` | 可丢帧的音频副本/分析摘要，不提供主图可写缓冲 |
| `system.media` | 经声明的媒体控制、快捷键与元数据服务；生命周期归宿主登记 |

宿主 API 默认不提供未声明的外部网络、设备、进程派生和任意文件访问。原生插件仍可绕过 API 直接调用系统功能，因此界面和文档不得承诺这些操作被强制阻止。不能接受这一信任边界的包应保持禁用；若未来要求安全运行不可信原生代码，当前单进程模型不能满足，必须先提出架构冲突。

主题只提供声明式颜色、字体、尺寸与受限布局 token；React 负责将 token 映射为既定组件样式。在本次已启用的主题之间切换资源可即时生效，不重启音频引擎；主题插件本身的启用/停用与版本切换仍在重启后生效。资源损坏或接口不兼容时回到默认主题。

`control.api` 默认关闭。启用后默认仅本机访问，使用独立可撤销 token；浏览器调用还验证来源。网络协议和本地 IPC 的具体选择留待原型验证。请求携带 `commandId` 和必要的播放代次/修订，经 PlayerCore 做鉴权、参数校验与去重；订阅带序号，缺失后重新获取快照。

远程监听须显式配置监听范围、鉴权和安全传输。停用插件只保存下次启动禁用，当前监听/订阅保持到应用退出；退出时停止接收并释放订阅。独立 token 撤销立即阻止该 token 的新请求，用于即时收回某调用方权限，不等同于插件停用。播放控制权限不包含插件安装、权限变更、任意命令执行或凭据读取；调试日志使用英文且隐藏 token、私有地址和敏感头。

## 7. 实施顺序与验收

C0 先冻结最小包清单与 C ABI 草案，用一个主题包、一个按 CMake/C++23 构建的增益 DSP 动态库，以及可注入可返回错误、协作取消失败和进程崩溃的测试库验证方案。故障测试使用独立的测试 Client 运行，生产插件不因此采用额外进程模式。记录各 target、系统、构建工具链、设备、块尺寸、欠载、CPU/内存及取消耗时；数值预算通过实测写入验证记录后才作为发布门槛。

后续按主计划交付安装事务、宿主 SDK、真实加载、管理页、更新回滚和崩溃后禁用插件的恢复入口。每项验收使用打包后的应用及从磁盘安装的包；开发服务器和静态内置样例仅作辅助。C++ 插件记录 CMake 配置、C++23 编译选项及实际标准库/运行库依赖；无对应 target 证据时不能宣称支持。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 应用发布后安装新的 DSP 包 | 不重新编译客户端，保存启用并重启后从磁盘装载，实际改变测试音频 |
| 三大平台及声明 CPU target | 主题可用，原生包只选择匹配入口；不匹配/缺依赖明确拒绝，不静默使用其他 ABI |
| 旧 ABI、未知必需能力、配置不兼容 | 加载前尽可能拒绝；加载后发现不兼容不注册能力，库仍保留到退出，不在同进程改加载其他版本 |
| 坏摘要、越界路径、链接逃逸、超大包 | 安装失败，未写出安装根，活动版本和配置不变 |
| 连续切歌、seek、取消后延迟返回 | 旧播放/装载代次输出被丢弃，状态、歌词和设备输出一致 |
| 播放中请求停用 DSP | 只变更期望值并提示重启，当前图/能力保持；重启后不加载已禁用包 |
| 正常切歌、换图与应用退出 | 实例/回调/缓冲按顺序回收，所有已加载库保持引用到进程退出，没有主动库卸载 |
| 插件返回错误或畸形 PCM 描述 | 宿主校验后拒绝错误数据，回调不等待控制任务；可恢复路径按 PlayerCore 策略运行 |
| 同进程插件故意访问违例或堆破坏 | 允许整个测试 Client 终止；下次启动能禁用疑似包并保留诊断，不将 catch 宣称为故障隔离 |
| 进程内插件拒绝退出 | 标记需重启并保留必需引用，不强杀线程，不承诺卡死进程能正常退出 |
| 更新中断、迁移失败、切换失败 | 旧版本及原配置可用；重启能从安装日志恢复明确状态 |
| 新版本启动崩溃与人工回滚 | 下次启动阻止疑似版本，选定旧版本后重启恢复，失败次数和原因可查询 |
| 未授权的宿主服务调用 | 宿主 API 拒绝并脱敏记录；直接系统调用不保证受限，安装说明和设置不得宣称原生沙箱 |
| 主题异常、反复切换与歌词窗口开关 | 默认资源可恢复，不改变播放状态、不重启音频引擎 |
| UI/API 并发、token 撤销与待停用 | 命令按唯一核心顺序执行，撤销 token 即时阻止其新请求；插件停用仍显示待重启 |

发布记录须区分“内置适配器可用”“用户主题可安装”“重启后动态装载”“重启启停/版本切换”和“故障恢复已验证”。所有原生包均按同进程信任模型发布，不设置或声称第三方故障隔离；某项未通过时标为未支持，不用“插件系统完成”概括全部能力。
