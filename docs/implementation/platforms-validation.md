# 跨平台交付与验证

状态：实现计划；2026-10-10。桌面 Client 已选 React + TypeScript + Tauri 2 + Rust，尚无可运行实现。本文件中的目标、验收条件和候选后端均不表示已支持；所有 Client 验证记录初始为“待验证”。阶段编号沿用[实施计划](../implementation.md)。

## 1. 支持范围与版本冻结

Windows、macOS、Linux 均为桌面目标。C0 在三个系统上验证最小窗口、原生音频、插件装载和生命周期，再冻结首版支持矩阵。不能以某个平台编译成功、浏览器预览成功或虚拟设备输出成功，替代目标系统实机验收。

| 目标 | 首轮验证架构 | UI 运行时 | C0 必须确定 | 当前状态 |
| --- | --- | --- | --- | --- |
| Windows | x86_64；arm64 另列扩展项 | WebView2 | 最低系统版本、运行时部署方式、安装包、设备输出后端 | 待验证 |
| macOS | arm64、x86_64 分别验证 | WKWebView | 最低系统版本、两种架构的原生依赖、签名及公证流程 | 待验证 |
| Linux | x86_64；arm64 另列扩展项 | WebKitGTK | 首批发行版及版本、桌面环境、X11/Wayland、音频服务与打包基线 | 待验证 |

Tauri 在三平台使用的 WebView 不同，Windows 为 WebView2，macOS 为 WKWebView，Linux 为 WebKitGTK；前端语法、CSS 和交互必须按实际运行时验证。[官方 WebView 说明](https://v2.tauri.app/reference/webview-versions/)

C0 将 React、TypeScript、Tauri CLI / Rust crate / JavaScript API、Rust 工具链、Node.js 与包管理器、C/C++ 工具链、音频库、FFmpeg、插件 SDK 和 Server 协议版本写入版本清单及对应锁文件。本文不预填未经构建验证的版本组合；主仓库 Web/Server 的工具版本不自动成为 Client 的兼容承诺。

每个发布目标有独立结果：`OS + OS version + arch + WebView + audio backend`。Linux 追加发行版、桌面环境、显示会话与音频服务版本。未测试的架构不因模拟运行或同一源码而标记支持；最低支持系统版本也不得直接照搬框架文档。

## 2. 平台能力矩阵

以下均为计划。平台适配层返回可用能力、限制和失败原因，界面按实际能力展示；不得在调用失败后仍显示已经开启。

| 能力 | Windows 验证点 | macOS 验证点 | Linux 验证点 | 能力不可用时 |
| --- | --- | --- | --- | --- |
| 主窗口与独立歌词窗口 | 窗口重建、焦点、任务栏行为 | 关闭窗口、激活应用、全屏与工作区 | 多窗口、窗口管理器与工作区 | 保留主窗口内歌词 |
| 歌词透明与置顶 | 透明背景、全屏应用覆盖边界 | 透明、窗口层级、全屏空间及分发限制 | 合成器及窗口管理器差异 | 不透明普通窗口；解释限制 |
| 鼠标穿透、锁定与解锁 | 穿透后可从托盘/主窗口恢复 | 输入区域与焦点恢复 | X11、Wayland 分开验证 | 禁用穿透，保留拖动和关闭入口 |
| 托盘与后台入口 | 点击、菜单、重启后图标恢复 | 菜单栏图标与应用激活 | 桌面环境是否提供托盘及菜单 | 不启用无入口的隐藏运行 |
| 媒体键及系统媒体控制 | 播放、暂停、切歌与元数据同步 | 系统控制与焦点切换 | 桌面媒体集成及快捷键冲突 | 保留应用内控制，显示不可用 |
| 凭据存储 | 用户级系统安全存储候选 | Keychain 候选 | Secret Service 等候选，锁定/缺失情形 | 仅本次会话使用，提示重新登录 |
| 音频设备与热插拔 | 输出候选后端、默认设备改变 | 输出候选后端、设备及采样率变化 | 音频服务组合、断连与重启 | 明确停止/重新选择，不静默切到意外设备 |
| 多屏与缩放 | 混合 DPI、负坐标、屏幕断开 | Retina、外接显示器、工作区切换 | 分数缩放、X11/Wayland 坐标 | 将窗口恢复到可见区域 |

窗口控制统一经 Rust 平台适配层执行。歌词窗口不直接获得启动进程、读凭据、安装插件或任意文件访问能力；主窗口和歌词窗口分别配置最小 Tauri capabilities。capabilities 约束 WebView 到原生层的访问，不为任意 Rust/C++ 代码提供沙箱。[官方权限边界](https://v2.tauri.app/security/capabilities/)

平台专属实现只在适配层使用条件编译，不在 React 业务页面散布系统判断。界面消耗平台能力快照；能力变化后重新渲染设置项，并保留用户偏好与当前生效状态的区别。

### 2.1 Linux 单独验证

X11 与 Wayland 分为两组证据；不能以 XWayland 下成功推断原生 Wayland 已通过。每组验证置顶、透明、定位、穿透、全局快捷键、托盘、焦点与跨屏拖动，记录合成器/桌面环境及显示后端。

C0 不假设所有窗口管理器都允许相同的窗口行为。若某组合无法实现穿透、全局定位或置顶，记录限制并采用矩阵中的退化行为；原生补充接口须独立评估权限和分发条件。普通音乐库、播放和窗口内歌词仍按核心功能验收。

### 2.2 窗口与进程存活

关闭主窗口与退出应用是不同命令。计划默认：关闭主窗口关闭应用；用户启用“关闭后在后台运行”且有已验证的恢复入口时，改为隐藏主窗口，保持 Rust 主进程、PlayerCore、插件宿主与连接运行。macOS 关闭窗口和退出应用的呈现按系统惯例细化，仍使用同一显式生命周期规则。

托盘/菜单栏不可用且不存在其他可靠恢复入口时，不进入无窗口且无法恢复的状态。歌词窗口关闭只取消歌词显示，不停止音频；WebView 刷新/崩溃不应重置 PlayerCore。重开主窗口按主计划等待订阅建立、缓存事件，再原子读取 Rust 权威快照与状态序号，合并连续新事件；进度独立序列可合并，避免初始化期间丢失状态变化。

“退出应用”停止接收新命令，完成播放器和插件的有界收尾，取消并等待续租任务结束，再注销当前会话，由 Server 撤销对应播放与租约，最后退出 Rust 进程。单独 release 仅用于保留会话而脱离实例的流程；最后租约 release 后不能保证 Server 仍接受注销。挂起、恢复、锁屏、系统退出和强制终止均列入验收；崩溃后的回收由 Server 租约机制处理，不能假定退出回调必定执行。详情见[接入与收尾](server-integration.md#3-事件并发和生命周期)。

## 3. 安装包与原生依赖

### 3.1 两类交付物

| 交付物 | 内容与使用方式 | 边界 |
| --- | --- | --- |
| 桌面 Client 包 | React 静态资源、Rust/Tauri 可执行程序、已验证的原生音频依赖与内置 Client 插件 | 可独立连接 remote 或 external-local Server，不要求安装本地 Server |
| 可选 managed-local 配套包 | 与 Client 协议兼容的 Server、官方 Server 插件和受控启动配置 | 显式选择后启用，独立记录 Server 版本、目标架构与兼容范围 |

现有[主仓库组合打包](../../../docs/packaging.md)面向 Web + Server，主要目标为 Windows/Linux，不能作为桌面 Client 包已经可用的证据。macOS Client 连接 remote Server 与 macOS managed-local 是不同验收项；后者需另行验证 Server、插件、音频工具、文件权限、启动和退出的本机交付，不能从 Go 交叉编译成功推断支持。

包按 OS/arch 分发，所有动态库和可执行插件必须匹配目标。macOS 先为两种架构分别验收；若提供通用包，额外验证其中每个原生依赖、插件和启动路径。Linux 首版格式在 C0 确定，包格式本身不代表覆盖全部发行版。

Tauri 构建依赖随平台变化：Windows 使用 Microsoft C++ Build Tools 与 WebView2，macOS 使用 Xcode 相关工具，Linux 需要对应发行版的 WebKitGTK 等系统开发库。具体安装与运行依赖清单以锁定版本和干净环境实测为准。[官方环境准备](https://v2.tauri.app/start/prerequisites/)

### 3.2 制品清单

每个 Client 制品至少记录以下内容，缺项不进入发布验收：

- Client 版本、Git 提交、工作树状态、OS/arch、构建工具版本与依赖锁摘要。
- WebView 运行时要求、检查方式、缺失时处理与离线安装路径；macOS/Linux 的系统依赖范围按实测填写。
- Rust/C/C++ 原生库和 FFmpeg 的版本、构建选项、来源、依赖、哈希与许可证材料；是否随包提供逐项说明。
- Client 插件 SDK/ABI 版本、内置插件清单、可加载插件架构，以及 Server 协议兼容范围。
- 安装目录、可写用户数据目录、插件目录、日志目录、卸载保留规则和升级恢复入口。

FFmpeg 作为 Client 解码适配候选时，须验证实际加载的库及其依赖；不能依赖开发机 PATH 中碰巧存在的工具。Client 内置 FFmpeg 与 Server 外部 FFmpeg/ffprobe 是两个部署项目，版本和用途分别记录，不互相覆盖。C++ 封装层采用明确的 C ABI 边界，发行时验证运行库和符号依赖。

应用、插件和用户数据分目录存放。包中不含开发配置、音乐文件、数据库、令牌、凭据导出或签名私钥；凭据存储失败不回退到普通 JSON 明文持久化。安装、升级和卸载不得默认删除音乐库或用户插件数据。

### 3.3 签名与发布

平台应用/安装包签名、公证与更新包签名分别配置、分别验证；Tauri 分发文档列有各平台流程。若采用 Tauri updater，其更新签名校验是必需项，不能以 HTTPS 或文件哈希替代。[官方分发](https://v2.tauri.app/distribute/)、[官方 updater](https://v2.tauri.app/plugin/updater/)

这些发行签名与开发 Git GPG 签名是不同机制。仓库继续遵守“未明确要求推送时不进行 GPG 签名；明确要求推送时先补签尚未推送的旧提交”；编写本计划不触发签名、发布或推送。发布凭据和私钥通过受限环境注入，不能进入 Git 或安装包。

首次发行验收应从干净系统安装正式制品，检查依赖缺失、非 ASCII/带空格路径、普通用户权限、旧配置、插件禁用状态、卸载保留与重新安装。开发模式成功不能替代已签名制品验证。

## 4. 本地 Server 与升级恢复

连接模式、启动归属和租约以[总体架构](../../../docs/architecture.md)与[Server 生命周期](../../../server/docs/lifecycle.md)为准。Rust 连接管理器维护身份检查、授权会话及租约续期，不依赖 React 定时器、窗口可见性或 WebView 是否存活。

当前 Server 文档规定租约有效 30 秒、建议每 10 秒续租；实现同时读取 Server 返回的期限，按成功序号推进，原请求重试保持幂等。休眠/断线恢复后先验证实例和租约状态，过期租约不可复活；服务实例变化或进入 `draining` 时重新发现，不继续沿用旧实例令牌和播放会话。

| 情形 | 必须验证的行为 |
| --- | --- |
| remote / external-local | 不派生本地 Server，不自动提权或接管系统服务 |
| managed-local 首次启动 | 互斥、二次发现、固定目标与参数白名单、产品/实例/协议校验和有界就绪等待 |
| 主窗口关闭但后台运行 | Rust 继续续租与处理播放；重新打开窗口不创建重复租约 |
| 多 Client 并存 | 一个退出不关闭其他 Client 使用的实例；不改变已有实例启动归属 |
| standalone 实例 | 无论 Client 退出或崩溃都不按托管策略停止 |
| 强制退出或首租约失败 | 按 Server 期限回收；检查无孤儿实例和同数据目录重叠进程 |
| 会话到期/注销、Server 重启 | 重新鉴权或提示用户，旧会话和旧租约不能继续使用 |

升级分为 Client、Client 插件和 managed-local Server 三类操作，不复用一个“覆盖目录”动作。升级前下载到暂存目录，校验来源、签名/哈希、架构及协议；与其他 Client 协调后才能停机替换托管 Server。外部部署的 Server 仅提示不兼容与管理员升级入口。

Client 升级保留连接配置、主题、插件配置和可恢复队列，重新启动后重新读取 Server 权威状态；不持久化已失效的流授权作为继续播放依据。插件升级须停止调用、确认宿主释放或退出后切换版本，保留禁用状态与旧制品恢复入口。

数据迁移前检查兼容范围、空间和备份/恢复条件。新版启动或就绪失败时保留日志、旧制品、配置与数据恢复入口；若已经发生不向后兼容的数据迁移，不直接用旧二进制打开新数据。界面准确区分可回退程序、需要恢复备份和需要人工处理。

## 5. 验证层次与阶段门槛

| 层次 | 计划覆盖 | 可以证明什么 | 不能替代什么 |
| --- | --- | --- | --- |
| React 组件与视图模型 | mock 桥接、状态快照、错误、取消、能力禁用、无障碍和交互 | UI 不依赖真播放器即可验证命令及状态呈现 | WebView 差异、真实设备和插件行为 |
| Rust 核心与协议 | PlayerCore 状态机、代次、修订、取消、租约时钟、事件恢复 | 核心规则与边界处理 | 实际 OS 窗口、调度与音频连续性 |
| 原生集成 | FFI、插件装载、音频图、凭据、窗口权限与命令校验 | 选定构建及依赖组合的集成行为 | 所有 OS/arch 或全部设备 |
| Server 联调 | 当前 OpenAPI/事件版本、真实授权、来源与播放恢复、生命周期 | 实际客户端和 Server 契约一致 | 其他协议版本未经验证的兼容性 |
| 制品实机验收 | 安装、播放、歌词、设备、后台运行、升级和恢复 | 对应完整环境与制品的可交付性 | 未列入矩阵的系统和环境 |

三平台构建是持续集成门槛，三平台实机验收是发布门槛。C0 完成技术可行性与版本冻结；C1—C6 每阶段记录新增能力与回归，C7 对拟发布制品重做关键流程。测试框架与自动化工具在 C0/C1 锁定，不预设某一 WebDriver 方案可覆盖三平台全部原生窗口。

### 5.1 必需场景

1. **音频与交互隔离**：真实设备连续播放、快速切歌、定位、设备切换/拔插、默认设备改变、睡眠恢复、网络断流；React 卡顿、窗口重建和重渲染不控制音频回调。记录缓冲欠载、错误与恢复过程，性能阈值由 C0 基线确定，不编造已达到的延迟。
2. **原生边界与权限**：非法参数、越权窗口、远程内容调用、未授权文件/进程访问、FFI 错误、畸形媒体、受限凭据不可用和日志脱敏。capabilities 通过后仍需验证 Rust 命令本身的鉴权与范围检查。
3. **插件完整生命周期**：运行后安装兼容插件并发现/加载；拒绝错架构、错 ABI、被篡改包与路径越界；验证启用、禁用、更新、卸载、重启持久化以及播放中更新的安全边界。同进程崩溃与独立宿主崩溃分开注入，不能把后者通过写成前者已隔离。
4. **协议与状态恢复**：UI 订阅晚到、断线重连、事件缺口、重复/乱序事件、播放代次取消、Server 重启、会话过期和协议不兼容；按订阅屏障和快照序号恢复，迟到结果不得覆盖当前曲目、队列或账号。
5. **生命周期**：关闭主窗口、退出应用、歌词单独关闭、托盘恢复、Rust/WebView 分别崩溃、多 Client 并发启动、首租约失败、最后租约释放与超时；验证实际进程存活与数据锁，不只观察窗口。
6. **发行与更新**：干净安装、缺少运行依赖、错误签名、下载中断、磁盘不足、文件占用、插件旧版本、Client/Server 不兼容、迁移失败及恢复；remote 模式全流程不需要本地 Server。

自动化测试使用隔离目录、测试凭据、确定性时钟和可控故障；真实账号、系统凭据及生产音乐库不进入测试制品。实机音频样本使用可分发、可追溯的测试材料，按格式、时长、采样率和声道记录，不把一个样本成功扩展为格式全覆盖。

后续验证记录放在 Client 的 `docs/validation/`，每条关联 C0—C7 阶段和缺陷/限制。当前尚未产生 Client 验证记录；以下表仅是待填写模板。

| 字段 | 初始值 / 填写要求 |

| 环境 | 待验证；OS/arch、WebView、设备；Linux 追加显示及音频服务 |
