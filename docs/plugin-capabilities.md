# Client 插件能力与宿主边界

状态：设计细化；2026-10-11。本文定义播放器后续拟扩展的插件能力接口，角色名和方法名均为待冻结的 SDK 草案。总体边界见[Client 架构](architecture.md)，安装与生命周期见[插件实施](implementation/plugins.md)，跨端约束见[插件职责](../../docs/plugin-boundaries.md)。

## 1. 架构判断与执行模型

现有 Rust PlayerCore 持有播放状态，解码、内置 DSP 和输出在本机运行。下文的 Client Plugin Host 是可安装插件的设计，其 SDK 和动态库装载仍待实施。原方案中的能力注册表可扩展，但新角色必须先定义接口、资源所有权和失败行为，不能只增加 manifest 字符串即宣称支持。

规划中的原生插件以动态库在 Rust 宿主同一进程中运行，目标产物包括 Windows DLL、macOS dylib 和 Linux so。未来的 managed-local Server 使用独立进程。

需要 C++ 的插件使用 CMake/C++23 和版本化 C ABI。桌面界面和播放器使用 Rust。构建、target、依赖及 ABI 规则见[原生插件规范](../../docs/native-plugins.md)。

原生插件和宿主拥有相同进程地址空间及系统权限；清单和宿主服务授权是合作式契约，无法防御恶意原生代码的直接系统调用或内存写入。安装页必须在启用前明确这一事实。可正常返回的错误可以映射为错误码；访问违例、堆破坏和部分死锁不能靠异常捕获恢复。采用此模型即接受插件故障可能结束整个 Client。

本期不提供插件卸载功能。所有插件的启用、停用、更新及回滚均在重启后生效，初次安装后启用也一样；本次已加载库及函数表保留到原生宿主进程退出，不主动卸载。停用设置只写期望值，当前活动版本和能力继续可用到退出，功能故障另行显示。

## 2. 固定在宿主的职责

| 宿主职责 | 插件可参与的方式 | 宿主保留的决定权 |
| --- | --- | --- |
| PlayerCore、队列、修订、播放代次 | 提交类型化命令或读取已授权快照 | 唯一状态写入、命令顺序、取消及恢复决定 |
| 输出时钟与图调度 | 报告输出帧、延迟、时间映射、格式及设备事件 | 校验并合成曲目时钟，决定活动图与切换边界 |
| Server 连接与受鉴权读取 | 获得当前尝试的有界读取/定位句柄 | 会话、Cookie/CSRF、续租、协议恢复及凭据保管 |
| 安装、信任与生命周期 | 提交包信息、能力及配置 Schema | 校验包、选择版本、授权宿主服务、持有动态库和图租约 |
| 窗口与凭据 | 使用限定功能的宿主服务 | 各窗口可用操作、用户确认、秘密存储与日志脱敏 |
| managed-local Server 管理 | 显示状态、提交受限连接命令 | 固定目标启动、互斥、实例身份、租约和升级协调 |
| UI 组件与用户选择 | 提供声明式 token、配置描述和分析数据 | egui 渲染、无障碍、安装/权限确认与设置持久化 |

宿主 API 不暴露任意动态库路径、任意命令执行、直接核心内存引用或 Server 凭据读取。此项约束 API 设计，不宣称可阻止同进程插件绕过接口。用户歌曲、账号、来源推荐和刮削仍由 Server 管理，Client 不另建 Provider/Scraper 体系。

## 3. 尽量可替换的能力目录

| 能力（拟定） | 插件职责与输入/输出 | 宿主边界与缺失行为 | 阶段 |
| --- | --- | --- | --- |
| `theme` | 声明式颜色、字体、尺寸、受限布局与校验资源 | 不运行脚本；原生控件解释主题字段，失败回默认主题 | C4 |
| `audio.demux` | 受控输入句柄 → 流描述、带时基的数据包；探测和定位 | 探测有字节/时间预算，不直接持有账号凭据；无可用项则报告格式不支持 | C2 内置，C3 安装包 |
| `audio.decode` | 编码包 → PCM、格式变化和解码延迟 | 不写设备，不自发切歌；回退须重建本机解码图，输入恢复仍服从表示能力 | C2 内置，C3 安装包 |
| `audio.dsp` | PCM → PCM、延迟/尾音/时间映射；均衡、增益、采样/声道转换等显式节点 | 处理顺序及 Server 已生效效果由宿主确定；旁路须满足格式和时钟条件 | C3 |
| `audio.output` | 枚举设备、协商格式、打开/启动/停止、消费宿主 PCM；报告输出帧与延迟 | 宿主持有输出选择、回调缓冲和时钟；缺失/设备丢失则暂停并提示 | C2 内置，C3 安装包 |
| `audio.visualizer` | 有界 PCM 副本/降采样摘要 → 电平、频谱等声明式数据 | 只读旁支，可丢帧；不反向阻塞音频图，不提供可执行 UI 脚本 | C4 扩展 |
| `control.api` | HTTP/本机 IPC 等协议 → 已授权 PlayerCore 命令、状态订阅 | 默认关闭；鉴权、命令幂等与权限范围由宿主核验 | C3 |
| `control.integration` | 媒体键、系统媒体会话或外部设备事件 → 同一命令；反向发布精简元数据 | 窗口/凭据仍归宿主；系统专属能力逐平台验证，不可用时保留 UI 控制 | C4 扩展 |

内置 FFmpeg、WMF、增益、输出和系统控制适配器使用相同角色契约。内置包可以随安装制品提供，但新增兼容用户包须能从磁盘发现并装载，不能把编译时注册等同于可安装插件。

主题仍是数据包，无需为了“统一”引入 C++ 或动态库。外部控制协议插件、分析器及其他适配器按实际依赖选用 Rust 或 C++；使用 C++ 时遵循 CMake/C++23，不能穿透 C ABI。

## 4. 角色接口的最小要求

各原生角色共用 `query/create/configure/start/cancel/reset/destroy` 生命周期及结构体长度、版本、错误码、句柄规则。接口表只包含实际支持的方法；必需方法缺失时拒绝该能力，不能在首次播放时才访问空指针。

| 能力 | 必须补齐的方法/语义 | 关键验收 |
| --- | --- | --- |
| 解复用/解码 | `probe` 的读取预算、`readPacket`/`decode`、seek/reset、输入结束与 drain、格式变化事件 | 试探失败释放句柄；编码流结束与暂时无数据区分；不混用旧代次包 |
| DSP | `negotiate`、最大块尺寸、`process`、延迟/尾音更新、是否可旁路、时间映射类别 | 采样率或延迟变化要求重协商；未知映射不能伪造歌词时钟 |
| 输出 | `enumerate/open/start/stop/close`、格式/块尺寸、呈现帧计数、设备丢失及回调注销确认 | 回调停止、线程退出后才能销毁设备实例；库仍保留，设备时间不可靠时明确限制定位精度 |
| 可视化 | 订阅格式、可丢弃序列号、最大输出尺寸、更新频率、reset | 过慢时丢帧/停止故障分析任务；插件启用状态不变，音频时钟与主图不等待消费者 |
| 控制 | 命令集合、来源标识、授权上下文、订阅序号、关闭入口 | 重复请求不重复切歌；撤销后阻止新命令；退出回收系统回调 |

插件不得把宿主调用当作任意线程可重入接口。每个方法须声明线程、串行/并发要求、借用缓冲有效期及回调是否允许重入；默认实例调用串行，取消使用 Host 提供的原子令牌，或明确声明可并发且非阻塞的专用入口，不能排在可能卡死的 `process` 后面。只有明确标记的查询接口可并行。Host 将插件事件入队，PlayerCore 串行处理，不在插件回调中递归执行播放命令。

输出插件的系统音频回调是特殊实时路径：只执行已经审计的设备适配和宿主预分配缓冲消费，不加载库、不分配、不卡锁、不调用解码/DSP 控制入口。实际 DSP 默认在非实时处理任务运行，输出回调只消费已完成音频块；能够承受延迟的分析器另走可丢帧旁支。

## 5. 能力选择与音频图

选择顺序为：用户固定选择（若兼容）→ 用户配置优先级 → 宿主发布的默认优先级。插件不能自行抬高全局优先级。宿主先筛 target/ABI/配置，再按能力描述和有界实际探测挑选，记录每次失败原因；不能把扩展名声明当作已成功解码。

一个音频图只选择一个活动输出设备实例；解复用/解码可以由同一包提供，但所有权和 reset 边界必须清楚。图中每个节点记录 `pluginId + packageDigest + capabilityVersion + configDigest`，以及播放代次、格式、延迟和时间映射；配置含秘密时只记录脱敏标识，不能哈希后就随意公开。

格式转换作为显式 DSP 节点，不在输出或解码插件内部静默改变对外格式。新增处理参数先在候选图协商；成功后由 PlayerCore 在停止/明确图边界切换，再退役旧实例。本地处理图有独立的 `graphGeneration`；纯 Client DSP、设备或解码图改变不要求 Server 创建新 attempt，只有服务端来源/资产/表示/处理输出需改变时才重新协商。回调须同时匹配本地图代次、播放代次和插件实例代次。图/实例调整不改变插件启用状态或所加载的包版本；版本更新与回滚一律下次启动切换，没有运行中更新例外。

Server 已执行的效果由播放描述确认；Client 只补齐未执行的本地效果。转场时序、后端回退、同曲恢复和跨源续播由 PlayerCore 决定，插件只执行被选定的处理任务，不自行切换来源或网络地址。

## 6. 配置、资源与错误

配置由版本化 Schema 描述，原生界面使用内置控件生成设置。扩展包声明设置项、允许值及资源，不提供界面代码。运行中可调整的处理参数需声明范围和生效边界；格式、延迟或时间映射变化通常要求重建实例。插件启停、版本或权限清单变化使用待重启设置，不借参数调整绕过重启规则。已启用主题之间选择声明式资源可即时生效，主题插件本身启停仍待重启。

对插件开放的输入、存储、设备和控制服务使用不透明句柄、配额及作用范围；撤销后宿主 API 拒绝新操作。每个实例独立登记线程、回调、缓冲和输入租约。权限范围与配额只能约束这些服务，无法给同进程代码提供强制内存/CPU/系统权限隔离。

错误至少区分 `unsupported`、`invalid_config`、`input_unavailable`、`device_lost`、`cancelled`、`timeout`、`abi_mismatch` 与 `internal_error`，携带可公开诊断与私有日志关联 ID；不泄露 token、来源地址和原始配置。插件报告错误与进程崩溃分开：后者可能只能在下一次启动从不完整运行标记中识别，标记仅表示可疑实例，不能直接证明唯一故障根因。

## 7. 关闭、恢复与验收增量

插件停用只保存 `desiredEnabled=false` 并提示“重启后生效”，不立即停止当前任务或能力。正常曲目/图结束时仍需收尾实例；应用退出时停止新业务，通过取消令牌或专用入口取消任务、撤销新订阅、停止回调，保留排空所需的生命周期入口和完成通知，待在途调用/线程退出后归还租约并销毁实例。所有已加载库保留到进程退出。超时只说明等待超限；不能推断代码已停止或强杀线程后继续使用其堆状态。

排空失败进入 `restart_required`，库和相关内存保持引用，禁止覆盖文件和再启用同一故障实例。界面仍响应时提示重启；界面也被卡住时需要用户结束整个 Client。下次启动提供禁用非必要用户插件的恢复入口，保留原包和配置供诊断，避免重复装载导致启动崩溃循环。

新增角色在[原有安装与重启验收](implementation/plugins.md#7-实施顺序与验收)之上补充：

1. 输出包可在不重编译 Client 的情况下安装，启用后重启再选择；拔插/关闭后回调和设备实例按顺序回收，库仍保留到退出，时钟只接受当前输出代次。
2. 可视化长期不消费或返回畸形结果时停止故障任务/丢帧，正常播放不等待；不得在主音频队列形成背压，不把故障处理等同于插件停用生效。
3. 系统控制插件请求停用后当前系统集成继续工作，重启后不注册其快捷键/回调；与 UI/API 的并发命令仍只有一个 PlayerCore 顺序。
4. 同一插件 target 分别构建、打包和装载；C++23/运行库/依赖不兼容在安装或装载时明确拒绝，不能跨平台尝试其他入口。
5. 故意不返回的测试插件不被强杀线程，保留必要引用，重启恢复入口可禁用它；故意崩溃的测试插件允许 Client 结束，下一次启动可避开问题包。测试环境独立，不宣称进程内故障隔离。

若新需求必须运行不可信原生代码且要求其不能访问宿主内存、文件或网络，当前单进程插件架构无法满足；应先向用户说明冲突，再讨论需求或架构变更，不能以权限清单替代保护。
